<h1 align="center">Pulse Review</h1>

<p align="center">
  Небольшой self-hosted dashboard для анализа code review в GitLab.
</p>

Pulse Review показывает, сколько ревью провёл каждый участник команды, сколько
комментариев оставил, сколько merge request создал и как меняется вовлечённость
за выбранный период. Один GitLab может использоваться для нескольких команд с
разными правилами подтверждения ревью.

## Возможности

- статистика по одной или нескольким GitLab-группам и проектам;
- отдельные команды и списки участников;
- три способа подтверждения ревью: GitLab Approve, 👍 на MR или любой из них;
- исключение самоаппрувов и повторного подсчёта одного MR;
- approvals/👍, оставленные комментарии, созданные и открытые MR;
- комментарии, полученные автором к его MR;
- график вовлечённости: `review approvals + comments + created MR`;
- фильтры по команде и периоду;
- экспорт таблицы в CSV для Excel.

## Требования

- GitLab с доступным REST API v4;
- GitLab access token со scope `read_api`.
- Go 1.27 или новее нужен только при сборке из исходников. Для готового
  релизного бинарника Go устанавливать не нужно.

## Запуск готового релиза

1. Откройте [последний релиз](https://github.com/margaritayuki/pulse-review/releases/latest).
2. Скачайте файл для своего компьютера:

| Платформа | Файл |
|---|---|
| Mac с Apple Silicon (M1 и новее) | `pulse-review-macos-arm64` |
| Mac с процессором Intel | `pulse-review-macos-amd64` |
| Windows x64 | `pulse-review-windows-amd64.zip` |

3. Запустите Pulse Review и настройте GitLab в открывшемся браузере. Файлы
   конфигурации создавать вручную не нужно.

### macOS

В Terminal перейдите в папку с загруженным файлом и выполните:

```bash
chmod +x pulse-review-macos-arm64
./pulse-review-macos-arm64
```

Для Intel Mac используйте имя `pulse-review-macos-amd64`. Затем откройте
[http://127.0.0.1:4567](http://127.0.0.1:4567). Если macOS заблокировала первый
запуск, разрешите приложение в **Системные настройки → Конфиденциальность и
безопасность**.

### Windows

1. Полностью распакуйте `pulse-review-windows-amd64.zip`.
2. Дважды нажмите `start.cmd`.
3. Pulse Review откроется в браузере автоматически.

> После перезагрузки компьютера локальный сервер нужно запустить снова.

## Сборка из исходников

Нужен Go 1.27 или новее.

```bash
git clone https://github.com/margaritayuki/pulse-review.git
cd pulse-review
go run .
```

На Windows выполните те же команды в PowerShell. Затем откройте
[http://127.0.0.1:4567](http://127.0.0.1:4567). Для локальной сборки также
доступны `bin/setup` на macOS и `setup.cmd` на Windows.

## Как создать GitLab token

1. Откройте GitLab → **Preferences / Edit profile**.
2. Перейдите в **Access → Personal access tokens**.
3. Создайте токен, например `pulse-review`.
4. Выберите только scope `read_api`.
5. Скопируйте токен сразу после создания и введите его в разделе **Настройки**.

Токен будет сохранён только локально в `data/connection.json`. Не добавляйте
этот файл в Git и не пересылайте его другим пользователям.

## Первая настройка

1. Откройте вкладку **Настройки**, укажите адрес сервера GitLab и личный token,
   затем нажмите **Проверить и сохранить**.
2. В разделе **Источники GitLab** добавьте ссылку или путь группы/проекта:
   - `my-group`;
   - `my-group/my-project`;
   - `https://gitlab.example.com/my-group/my-project`.
3. Добавьте команду и перечислите GitLab usernames её участников.
4. Выберите способ подтверждения ревью:
   - **Approve** — системное событие GitLab `approved this merge request`;
   - **👍 Лайк** — реакция `thumbsup` на самом MR;
   - **Approve или 👍** — любой сигнал, но один человек + один MR считаются один раз.
5. Нажмите **Сохранить настройки**.
6. Вернитесь в **Статистику**, выберите период и нажмите обновление.

Настройки сохраняются локально в `data/*.json` и не публикуются в Git. Файл
`data/connection.json` содержит token; остальные три JSON-файла его не содержат.

## Как поделиться настройками команды

Можно передать коллегам структуру команд и источников GitLab, не передавая
GitLab token. Для этого отправьте только следующие файлы:

```text
data/routes.json
data/groups.json
data/projects.json
```

В них находятся:

- названия команд и GitLab usernames участников;
- пути групп и проектов GitLab;
- выбранный способ подтверждения ревью;
- параметры Mattermost, если функция была настроена.

В этих файлах нет GitLab token и рассчитанной статистики, но они содержат
внутренние usernames и пути проектов. Передавайте их только по разрешённому в
вашей организации каналу.

### Что делает отправитель

1. Остановите Pulse Review или завершите сохранение настроек.
2. Откройте папку приложения.
3. Упакуйте три JSON-файла из папки `data` в архив.
4. Не добавляйте в архив `data/connection.json`, `.env.local`, логи и бинарник,
   если коллега уже скачал его со страницы релиза.

На macOS архив можно создать командой:

```bash
zip pulse-review-settings.zip data/routes.json data/groups.json data/projects.json
```

На Windows в PowerShell:

```powershell
Compress-Archive -Path data\routes.json,data\groups.json,data\projects.json -DestinationPath pulse-review-settings.zip
```

### Что делает получатель

1. Скачивает подходящий бинарник из официального релиза.
2. Вводит собственный GitLab token в веб-интерфейсе.
3. Создаёт рядом с бинарником папку `data`.
4. Копирует полученные JSON-файлы в `data`. Существующие файлы с такими именами
   будут заменены, поэтому их лучше предварительно сохранить.
5. Запускает Pulse Review и проверяет вкладку **Настройки**.

Доступ к данным определяется токеном получателя. Если у коллеги нет доступа к
переданным группам или проектам, Pulse Review покажет ошибку GitLab API —
передача JSON-файлов не предоставляет дополнительных прав.

## Как считаются показатели

| Показатель | Правило |
|---|---|
| Approvals / 👍 | Уникальная пара `ревьюер + MR` согласно настройке команды |
| Комментарии | Несистемные комментарии сотрудника в чужих MR |
| Создано MR | MR, созданные сотрудником в выбранном периоде |
| Комментариев к MR | Комментарии других участников в MR сотрудника |
| Открыто MR | Созданные в периоде MR, которые ещё открыты |
| Вовлечённость | Approvals/👍 + комментарии + созданные MR |

Самоаппрувы, собственные лайки и комментарии автора в своём MR не учитываются
как ревью. Значение вовлечённости — прозрачная сумма активности, а не оценка
качества работы разработчика.

## Производительность

Pulse Review получает MR из настроенных источников, а затем загружает notes и
reactions для восстановления истории ревью. Первый запрос по большому периоду
может занять время. Повторные одинаковые отчёты кэшируются на 15 минут.

Для ускорения:

- выбирайте разумный период;
- добавляйте конкретный проект вместо большой группы, если нужны данные только
  по нему;
- не дублируйте один источник как группу и как проект.

## Решение проблем

### `Failed to fetch`

Страница должна открываться через `http://127.0.0.1:4567`, а не через
`file:///.../public/index.html`. Убедитесь, что Pulse Review запущен через
`bin/start` или `start.cmd`.

### `GitLab API: 401`

Токен неверный, истёк или отозван. Создайте новый токен со scope `read_api`.

### `GitLab API: 403`

У владельца токена нет доступа к группе или проекту либо доступ к API ограничен.

### `GitLab API: 404`

Проверьте адрес источника и доступ владельца токена к приватному проекту.

### Пользователь не найден

В составе команды нужно указывать GitLab username, а не ФИО или email.

## Безопасность и приватность

- сервер слушает только `127.0.0.1`;
- токен хранится локально в `data/connection.json` с правами доступа только для
  текущего пользователя;
- интерфейс не получает и не показывает токен;
- статистика может содержать персональные рабочие данные — учитывайте правила
  вашей организации перед публикацией отчётов.

Подробнее: [SECURITY.md](SECURITY.md).

## Разработка

```bash
go test -race ./...
go vet ./...
go run .
```

Основные файлы:

- `main.go` — API, GitLab-интеграция и локальное хранение настроек;
- `public/index.html` — интерфейс dashboard;
- `data/` — локальные настройки, исключённые из Git.

### Миграция v0.2.0

Стандартные команды уже запускают Go-версию:

```bash
bin/setup
bin/start
```

На Windows используйте `setup.cmd` и `start.cmd`. Миграция backend на Go
завершена; Ruby и Bundler больше не требуются.

## Версионирование

Проект следует [Semantic Versioning](https://semver.org/). Пока публичные
сценарии и формат настроек развиваются, используются версии `0.y.z`:

- исправления без новых возможностей: `0.1.0` → `0.1.1`;
- новые совместимые возможности: `0.1.x` → `0.2.0`;
- первая стабильная версия с зафиксированными сценариями: `1.0.0`.
